
# Wellness Wave 🌊

### Your Phone Tracks Your Time. Wellness Wave Understands the Pattern.

Wellness Wave is an Android-based behavioral wellbeing platform that goes beyond traditional screen-time statistics.

Instead of treating screen time, app usage, unlocks, and other metrics as isolated numbers, Wellness Wave combines behavioral signals to identify meaningful usage patterns and provide timely, actionable interventions.

The platform combines **on-device behavioral sensing, machine learning, real-time monitoring, student-focused interventions, and premium focus support** into a single experience.


## Overview

Traditional digital wellbeing tools primarily answer:

> **How much did I use my phone?**

Wellness Wave explores a different question:

> **What pattern is my digital behavior forming, and what can I do about it?**

The application continuously processes behavioral signals such as:

- Screen time
- Unlock frequency
- App switching
- Typing behavior
- Scrolling behavior
- Night-time usage
- Social application usage
- Productive application usage

These signals are transformed into behavioral features and passed through the machine-learning inference pipeline.

The resulting behavioral state is surfaced through the application and can trigger appropriate awareness or intervention experiences.

## Core Capabilities

### 1. Behavioral Monitoring

Wellness Wave collects relevant smartphone behavioral signals through Android's native capabilities.

The monitoring layer includes:

- Screen-time measurement
- Application usage analysis
- Foreground application detection
- Unlock tracking
- Application switching
- Scrolling metrics
- Typing-related behavioral signals
- Night usage
- Social/productive application categorization

The system is designed around **behavioral patterns rather than a single metric**.

---

### 2. Machine Learning-Based Wellbeing Classification

Wellness Wave transforms raw behavioral telemetry into engineered features before performing inference.

The current inference pipeline uses 12 behavioral features:

| Feature | Description |
|---|---|
| `screen_time_minutes` | Total device usage |
| `unlock_count` | Number of device unlocks |
| `app_switch_count` | Frequency of application switching |
| `typing_speed_wpm` | Typing speed |
| `scroll_speed` | Scrolling behavior |
| `night_usage_minutes` | Usage during the defined night period |
| `social_app_minutes` | Time spent in categorized social applications |
| `productive_app_minutes` | Time spent in categorized productive applications |
| `night_ratio` | Night usage relative to overall usage |
| `unlock_intensity` | Unlock activity relative to screen time |
| `fragmentation_index` | Application-switching fragmentation |
| `agitation_score` | Derived behavioral activity indicator |

The pipeline follows:

```text
Smartphone Behavior
        │
        ▼
Telemetry Collection
        │
        ▼
Feature Engineering
        │
        ▼
Preprocessing
        │
        ▼
Machine Learning Model
        │
        ▼
Prediction + Confidence
        │
        ▼
Wellbeing State
````

Current behavioral states:

* **Balanced**
* **Stress**
* **Addiction**
* **Burnout**

> **Important:** These states are behavioral indicators generated by the application's machine-learning system. They are not medical diagnoses or clinical assessments.

# Study Rescue 🎯

Wellness Wave extends behavioral awareness into action through **Study Rescue**, a student-focused focus intervention system.

A user can start a study session and define the amount of time they want to focus.

While the session is active, Wellness Wave continues using the behavioral monitoring infrastructure already present in the application.

When distracting behavior is detected, the system can progressively intervene.

### Intervention Flow

```text
Start Study Session
        │
        ▼
Behavior Monitoring
        │
        ▼
Distraction Detected
        │
        ▼
Intervention
        │
        ▼
Repeated Distraction
        │
        ▼
Additional Intervention
        │
        ▼
Repeatedly Ignored
        │
        ▼
Focus Rescue
```

Study Rescue is intentionally built on the existing monitoring infrastructure rather than introducing a separate behavioral tracking service.

---

# Focus Rescue 🛡️

When repeated interventions are ignored, Study Rescue can escalate into **Focus Rescue**.

Focus Rescue provides a dedicated focus environment containing:

* A persistent countdown
* Remaining focus time
* A dedicated full-screen experience
* Temporary restriction of selected distracting applications
* Continued access to essential device/system functionality

The objective is not to lock the entire device.

Instead, Focus Rescue creates a temporary environment that helps users protect the focus commitment they originally made.

### Example

```text
┌─────────────────────────────┐
│                             │
│        FOCUS RESCUE         │
│                             │
│            ◯                │
│          44:32              │
│                             │
│      Your focus session     │
│        is still active      │
│                             │
│     Stay focused until      │
│       the timer ends        │
│                             │
│        Exit Rescue          │
│                             │
└─────────────────────────────┘
```

The Focus Rescue timer is based on absolute timestamps so that the countdown remains consistent across UI recreation.

Study sessions and Focus Rescue are also treated as separate concepts.

For example:

> A 90-minute study session may contain a 45-minute Focus Rescue period.

Completing Focus Rescue does not automatically complete the overall study session.

# Machine Learning

## Feature Engineering

The model does not operate directly on raw telemetry alone.

Derived behavioral features are calculated before inference, including:

* Night usage ratio
* Unlock intensity
* Fragmentation index
* Agitation score

This creates a structured feature representation of smartphone behavior.

```text
Raw Metrics
     │
     ├── Screen Time
     ├── Unlocks
     ├── App Switching
     ├── Typing
     ├── Scrolling
     ├── Night Usage
     ├── Social Usage
     └── Productive Usage
              │
              ▼
      Derived Features
              │
              ▼
        Preprocessing
              │
              ▼
       Random Forest
              │
              ▼
     Class Probabilities
              │
              ▼
     Behavioral State
```

---

## Model Evaluation

The current model was evaluated using a user-aware split:

```text
100 Users
│
├── 70 Users → Training
├── 15 Users → Validation
└── 15 Users → Test
```

Multiple models were evaluated, including:

* Logistic Regression
* Random Forest
* XGBoost
* HistGradientBoosting

The current Random Forest model achieved:

**1.00 test macro F1 on the synthetic unseen-user test set.**

This result reflects performance on the project's current synthetic dataset and should **not** be interpreted as evidence of clinical accuracy or real-world diagnostic performance.

The project is structured so that the model can be retrained as higher-quality behavioral data becomes available.

# Data & Persistence

Wellness Wave uses Room/SQLite for local behavioral history.

The current local behavioral record includes fields such as:

* Timestamp
* Screen time
* Unlock count
* Night usage
* Application switch count
* Scroll speed

Additional telemetry required by the live ML pipeline can be transmitted through the backend API without necessarily being part of the local Room schema.

This distinction allows the application to separate:

**local behavioral history**

from

**real-time inference telemetry**.

Wellness Wave uses Android platform capabilities to collect behavioral information required by its features.

# Responsible Use

Wellness Wave is a **behavioral wellbeing and self-awareness application**.

It is not intended to:

* Diagnose medical conditions
* Replace professional healthcare
* Provide clinical assessments
* Provide emergency intervention

Machine-learning predictions should be interpreted as behavioral indicators generated from the application's model and data.

Users should understand the permissions requested by the application and how behavioral data is used.

---

# Development Principles

Wellness Wave is designed around several principles:

### Behavioral context over isolated metrics

A single number rarely tells the complete story.

### Awareness before intervention

The system first identifies behavioral patterns before applying stronger interventions.

### Progressive intervention

Study Rescue escalates only when continued distraction warrants stronger intervention.

### Reuse existing infrastructure

Study Rescue builds on the application's existing behavioral monitoring infrastructure instead of creating a parallel tracking system.

### Responsible ML

Model performance is reported in the context of the underlying dataset and is not presented as clinical evidence.
